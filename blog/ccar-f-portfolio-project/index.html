Turn Your CCAR-F Prep Into a Portfolio Project

By CCA Practice Platforms · October 4, 2026

If you're working toward the Claude Certified Architect Foundations credential (CCAR-F) as a step into AI work, you'll eventually face two questions. The exam asks whether you can make sound architecture decisions with Claude. People you want to work with ask a simpler one: what have you built?

A credential tells people you passed an exam. A project shows them how you think. The good news is that you don't have to choose between preparing for one and building the other. Anthropic's exam guide already contains four hands-on exercises, and any one of them can become a portfolio project that does both jobs.

The four exercises in the exam guide

Section 8 of the exam guide (CCAR-F) lists four preparation exercises. Each states its objective, its steps and the exam domains it reinforces:

  • Build a multi-tool agent with escalation logic. An agentic loop with tool integration, structured error handling and escalation. It reinforces Agentic Architecture & Orchestration, Tool Design & MCP Integration, and Context Management & Reliability.
  • Configure Claude Code for a team development workflow. CLAUDE.md hierarchies, custom slash commands, path-specific rules and MCP server configuration for a multi-developer project. It reinforces Claude Code Configuration & Workflows and Tool Design & MCP Integration.
  • Build a structured data extraction pipeline. JSON schemas, tool use for structured output, validation-retry loops and batch processing. It reinforces Prompt Engineering & Structured Output and Context Management & Reliability.
  • Design and debug a multi-agent research pipeline. A coordinator delegating to subagents, context passing, error propagation and synthesis that keeps track of sources. It reinforces Agentic Architecture & Orchestration, Tool Design & MCP Integration, and Context Management & Reliability.

Between them, the four exercises cover all five exam domains.

Which one to build

Pick by where you want your career to go, then check it against your gaps.

By direction. If you're aiming at customer-facing AI products, the multi-tool agent with escalation logic is the closest match: it's a support agent that knows when to hand a case to a human. If you're heading toward developer tooling or platform work, configure Claude Code for a team, starting with our guide to writing an effective CLAUDE.md file. If your background is data or document processing, build the extraction pipeline. If research, analytics or complex automation interests you, the multi-agent pipeline is the most ambitious of the four.

By gaps. Each exercise reinforces two or three domains, so the project can do targeted exam prep too. Take the free diagnostic to see which domains need the most work, and favor the exercise that covers them.

If you can't decide, start with the multi-tool agent. It reinforces three domains, including Agentic Architecture & Orchestration, the largest on the exam at 27%. Our agentic architecture domain guide covers what that domain tests.

Turning an exercise into a portfolio piece

The exercises are written as practice. A few additions turn one into something worth showing.

Give it a realistic scenario. Don't build "an agent with three tools." Build a support agent for a fictional online store that handles orders, returns and refunds. The guide's own steps already point this way: the escalation exercise suggests a hook that blocks operations above a threshold amount and redirects them to an escalation workflow. A refund limit is exactly that.

Use the guide's steps as acceptance criteria. Every exercise lists steps you can verify. The extraction exercise asks you to check that the model returns null for missing information instead of inventing a value. The agent exercise asks you to handle both the "tool_use" and "end_turn" stop reasons correctly. Write those checks as tests in your repository, so anyone can see what "working" means.

Show the failures you designed for. This is where a project stands out. The agent exercise asks for structured errors with a category (transient, validation or permission) and a flag saying whether a retry makes sense. The research exercise asks you to simulate a subagent timeout and confirm the coordinator still produces a report that names its gaps. Include those cases and show the output. Our write-up of an agent that retried the same error 11 times shows why this matters.

Measure something. The research exercise asks you to compare parallel and sequential subagent execution. The extraction exercise asks you to process a batch of 100 documents and calculate total processing time against a deadline. Put the numbers in your README.

Explain your decisions. Section 1 (CCAR-F) says the exam tests informed decisions about tradeoffs. Your README should do the same: why this tool boundary, why a hook instead of a prompt instruction, why this schema field is nullable. A short "decisions" section is often more revealing than the code.

Keep secrets out. The Claude Code exercise asks you to configure an MCP server with environment variable expansion for credentials. Do the same everywhere: no API keys in the repository, ever.

A worked outline: the escalation agent

Here's how the first exercise could look as a finished repository:

  1. The scenario. A support agent for a fictional online store, with a refund limit above which a human must approve.
  2. Three or four tools with descriptions precise enough to tell similar tools apart, for example looking up an order versus looking up a customer, as the exercise asks.
  3. The agentic loop, continuing on "tool_use" and returning the answer on "end_turn".
  4. Structured errors with a category and a retry flag, and tests showing the agent retries a transient failure but explains a business rule to the customer.
  5. A hook that intercepts refund calls over the limit and routes them to escalation. It's enforced in code, not requested in the prompt. Our article on one question type the exam uses explains why that distinction matters.
  6. A multi-concern test, such as a message asking about a late order and a refund at once, showing the agent handles both and replies once.
  7. A README with the scenario, an architecture diagram, the decisions section and the test results.

Built properly, that project reinforces three of the five exam domains and gives you a concrete answer when someone asks what you've built with Claude.

What it does for your exam prep

Building forces the decisions the exam asks about. Reading that tool descriptions drive tool selection is one thing. Watching your agent pick the wrong tool because two descriptions overlap is another, and you won't forget it.

Then check your understanding against exam-style questions. Our 400 practice questions cover all five domains, with an explanation for every answer, so you can see whether what you learned while building transfers to scenarios you haven't seen.

Showing it off

Pin the repository on your GitHub profile. Add it to the Featured section of your LinkedIn profile, next to the credential once you've passed. On your resume, one bullet describing what you built and one decision you made is enough. Our guide to listing the CCAR-F on your resume and LinkedIn covers the rest.

One rule: build from the exercises in the published guide, never from exam content. Anthropic's exam policy treats disclosing exam questions or answers as misconduct, and a portfolio is the last place to risk your credential.

Where to start

If you're a developer, our breakdown of what transfers from software development to the exam will help you pick the exercise that stretches you most. Then choose a scenario, write the guide's steps down as your checklist, and build. By exam day you'll have practiced every decision the project required, and you'll have something to show for it.

FAQ

Do I need a portfolio project to pass the CCAR-F?

No. The exam guide presents the four exercises in Section 8 as hands-on preparation, not a requirement. Building one is simply an effective way to practice the decisions the exam tests.

Which exercise should I start with?

The multi-tool agent with escalation logic reinforces three domains, including Agentic Architecture & Orchestration, the largest on the exam at 27%. If your weakest domains point elsewhere, choose the exercise that covers them.

Can I publish my project publicly?

Yes, as long as it's your own work built from the published exercises. Keep API keys and credentials out of the repository, and never include exam questions or answers.

How many exam domains do the exercises cover?

All five between them. Each exercise reinforces two or three domains, as listed in Section 8 of the exam guide.
